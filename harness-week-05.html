本周目标

不用先学完整 Python 课程，只学习能理解、修改和验证工具所必需的部分。让 DSH 协助开发，你负责理解关键代码与验收。交付一个自己修改过的周报 CLI、一张数据流图与新增测试。

参考实现 src/report.py 已经可运行。学习时另建 src/report_student.py 实现简单版本，完成后再比较，不能把参考实现算作自己独立开发。

先认识最小语法

变量保存值；list 保存多项数据；dict 用键值表示一行；for 遍历；if 判断；def 定义函数；raise 报告失败。文件读取必须指定编码，CSV 应用 csv 模块解析，不要用字符串 split 处理含逗号与引号的单元格。

以下统计只在数据已校验后成立：

closed = sum(row['status'] == 'closed' for row in rows)
minutes = sum(int(row['minutes']) for row in rows)

布尔值在求和中按 1／0 计算。CSV 中读出的数字最初是字符串，要转换并检查范围。不要用 eval 解析文本，更不要把工单 text 拼成 shell 命令。

把开发任务交给 DSH

请先只读需求与参考实现，说明关键函数和数据流，不改文件。
随后帮我在 src/report_student.py 实现最小版本，不复制整份答案。
每次只增加一个能力，解释输入、输出和失败条件。
不得修改原始 CSV 或测试真值来让结果通过。
运行测试前告诉我命令；最终提供真实退出码和未完成项。

你可以要求先写读取函数，然后自己填统计逻辑，再让 DSH 审查。把思考交给模型、自己只按运行，不足以应对面试中的代码追问。

执行与核验

python -m src.report --dry-run
python -m src.report
python -m unittest discover -s tests -v

参考实现预期生成 output/weekly.md；四项统计与真值一致。自己的 student 版本按你设计的入口运行，不要误以为上述命令测试了尚未接入的 student 文件。必须给自己的函数写直接测试或改好测试导入。

dry-run 只表示本 CLI 不写报告，不等于任意程序带同名参数就安全；需读实现。原子写入通过同目录临时文件再替换，降低中断留下半文件的风险，但不等于完整事务或并发控制。

必做的小改动

自己增加 open 工单数，但不改输入数据。先写预期 open=4 的测试，再实现 closed 之外的统计，最后检查报告也显示该值。注意修改 summarize 的返回字段会影响已有完全相等断言：合理更新断言，同时保留原四项检查，不能删掉回归测试。

工作场景、面试与验收

问：为何让脚本算数、模型写解释？答：把确定性步骤交给可测试程序，把语言判断交给模型，并独立核验关键事实。

问：输入范围限制为什么还不算沙箱？答：只能约束该程序实现的路径；其他工具或 shell 仍可能越界。

问：AI 生成代码如何证明可靠？答：解释关键逻辑、检查差异、测试正常与异常输入、确认权限，不以作者是 AI 或回答自信作为依据。

验收：能解释读取、校验、统计、写入四个阶段；自己的修改有直接测试；失败不会写出看似成功的新报告。遇 ModuleNotFoundError 先检查项目根目录与 -m 用法，不随便 pip install 名称相似的软件包。
