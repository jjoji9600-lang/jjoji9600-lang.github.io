## 这周只做一件事：知道程序有没有算错，AI 有没有改错

测试可以理解为自动核对答案的小检查。它不是神奇的正确证明，只会检查你事先写好的情况。练习包里有六个检查，帮你先体验。

先备份：在文件资源管理器选中 requests.csv，Ctrl+C、Ctrl+V，保留副本；也复制 report.py 留一个副本。先不需要学 Git。

## 第36天：第一次运行检查

按上周方法，在练习目录打开终端，输入：

```powershell
python -m unittest -v
```

这条稍长，暂时整体理解为运行当前文件夹的测试。若你前面用 py，这里仍替换为 py。

**应该看到：** 六项检查，最后类似 Ran 6 tests 和 OK。英文 OK 表示这些检查通过；不代表所有真实业务情况都检查过。

把末尾结果记下来。显示 Ran 0 tests 不是全通过，而是没有找到检查，要先确认目录中有 test_report.py。

## 第37天：亲手验证输入变了，结果会不会跟着变

右键 requests.csv，选择打开方式 → 记事本，不要默认让陌生软件修改它。找到第一行数据末尾的 10，改成20，其他逗号和表头不动，Ctrl+S。

重新运行 python report.py，再打开 weekly.txt。**总分钟应从60变70，其他三项不变。** 这是你自己能核对的变化，不需要信模型。

完成后把20改回10，再运行一次，确认恢复60。测试中的原始数字检查只适用于原始材料，所以改数期间它失败是有原因的。

## 第38天：安全地制造一次错误

在确认有备份的情况下，将同一处分钟临时改为 -1，保存，再运行 report.py。

应该看到分钟不能是负数、没有生成新的周报，并且本轮没有成功提示。之前的 weekly.txt 可能还在，不要误以为新任务已成功。

把 -1 恢复10，保存重跑。**完成标志：** 知道合理失败是什么，不要求程序面对坏数据也硬做完。

## 第39天：让 DSH 先提方案，不立刻动手

发送：

```text
我想让 weekly.txt 第一行从模拟求助周报改成我的第一份AI周报。
先只读取 report.py，告诉我需要改哪里，暂时不写文件。
不改 requests.csv、不改任何计算、不改测试。
我确认后再做。
```

看它计划是否只涉及标题。这个改动很小，正适合练习控制范围。若它要重写整套项目，告诉它只改标题。

## 第40天：批准修改，亲自核对

确认后回复：可以，只改标题。查看 DSH 的实际修改记录，再用记事本打开 report.py，或在软件差异视图里查看。

差异就是修改前后哪里不同。你现在不需要懂全部代码，也应能确认只改了一句标题，没有改输入数据、没有删除校验。

运行 python report.py 和本周第一天的测试命令。确认新标题生效、四个数字未变、六个检查仍通过。

## 第41天：练习恢复，不用危险命令

本周先用最容易理解的恢复方式：找到你备份的 report.py 副本，复制回原文件名。系统询问是否替换时，先确认目标确实是本练习文件。

再运行程序，标题应恢复。然后决定是否重新做标题修改。不要为了撤销一句标题，照抄删除整个目录或强制重置的命令。

## 第42天：写一段失败记录

在 learn.txt 写下：我改了什么、预期是什么、实际看到什么、怎样恢复。写真实的一次即可，不要求漂亮格式。

**本周过关：** 知道测试成功和0个测试的区别；输入改变能预测输出；错误数据会停；AI 的修改必须自己看；能从副本恢复。

## 一个很重要的问题

六个检查全过，能不能说程序永远不会错？不能。它只是通过了这六个场景。以后逐步补更多检查，比说我已让 AI 检查过可靠。

工作和面试时，拿出一次真实失败与排查过程，比只说系统很稳定更有说服力。
