## 本周目标

让流程在没有长聊天上下文时仍能运行，记录失败、恢复与交接；再把安全的静态作品发布到你自己的 GitHub Pages。交付运行手册、恢复演练和公开作品页。

先实现手工可复现，再考虑 headless 与定时任务。没有稳定验收的任务，自动跑只会更快地产生错误。不要为了展示无人值守关闭安全审批。

## headless 入门

在专用测试工作区，先核对本机帮助：

```powershell
dsh --profile headless --help
```

确认该 profile 和参数在你的版本存在，权限已限制，然后再做一次只读实验：

```powershell
dsh --profile headless '只读取 README.md 并概述项目，不写文件、不运行命令、不联网。'
```

这是模型任务，可能产生 API 费用。提示中的限制仍需实际工具权限落实。headless 进程正常退出不代表业务任务成功，要继续验证产物与任务条件；先读当前版本关于输出与退出状态的定义。

定时执行是进阶选做：明确工作目录、环境变量注入、超时、最大并发、失败告警、预算和人工停机开关后再启用。Windows 可研究任务计划程序，Linux 可研究 cron／systemd timer，但本周不要求开长期任务。

## 恢复与幂等

运行顺序可以是：输入校验 → 确定性统计 → 可选模型分类 → 校验 → 渲染 → 人审。把每一步状态记下来。重复生成同一份本地报告可能只是覆盖产物；发送邮件、付款、修改工单则可能重复造成副作用，需要幂等键与事务／业务补偿等设计。

参考脚本原子替换单个报告，不包含完整工作流检查点、并发锁或精确一次执行保证。这些未实现能力应写在局限中。

恢复练习：先成功生成一次，再把输入文件名改为不存在，确认第二次失败不会被旧报告掩盖。恢复有效输入后重新跑，并记录新时间与状态。不要通过删除失败日志制造一直成功的假象。

## 发布自己的 GitHub Pages

初学者可在 GitHub 网页创建作品仓库并上传经审查的文件，不必先搭 CI。建议目录：

```text
README.md
src/ tests/ data/ evals/
docs/
  index.html
  architecture.md
  evaluation.md
  runbook.md
```

1. 在 docs/index.html 写一个简单静态页面，包含项目目标、架构、运行命令、真实测试与评测、限制和源码链接。
2. 只上传模拟数据和脱敏报告；不要上传 .env、环境导出、原始会话、账号截图或整份配置。
3. 在仓库 Settings → Pages 选择当前可用的分支发布方式，选择 main 与 /docs；菜单变更以 GitHub 文档为准。
4. 等待构建成功，打开 GitHub 给出的 URL；项目站通常包含仓库名路径，链接采用相对路径。
5. 刷新并检查 CSS、下载和源码链接，未部署成功不能在简历写已上线。

Pages 只提供静态内容。API 演示在本地或有鉴权的后端运行，不把 API Key 放进 HTML／JS，也不要把公开网页做成无限付费调用入口。

## 面试与验收

问：自动化任务怎么判断失败？答：进程状态、步骤状态、实际产物校验和业务验收联合判断。

问：重试为何危险？答：不确定服务端是否已执行，可能重复计费或产生副作用，需要幂等和可观测性。

验收：新环境可复现；至少一次失败与恢复证据；公开网页可访问且无凭证；没有把 headless 或静态页面夸成完整生产平台。
