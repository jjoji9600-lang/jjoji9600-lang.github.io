# 手机通过 DSH Go 控制服务器：随身运维入门

电脑不在身边，服务器却突然告警。除了手机 SSH，还可以用 DSH Go 连接服务器上的 DSH，通过对话检查状态、分析日志，并审批工具执行。

> 本文依据项目文档整理，未进行 Android 真机联调。DSH Go 是第三方项目，界面及要求以当前版本为准。

## 一、理解连接方式

管理服务器请选择远程主机，而不是手机本机引擎。通过 SSH 连接时，手机作为前端，服务器上的 DSH 才是实际执行工具的地方。模型请求仍由配置的模型提供方处理，不代表离线运行。

链路：DSH Go → SSH 隧道 → 服务器 DSH Web 服务 → 获准的工具操作。

这不是远程桌面。读取文件、执行命令的范围取决于服务器账户权限和工具审批策略。

## 二、服务器准备

先准备普通运维账户，并验证 SSH 可用。以下地址、用户名和端口需要替换：

```bash
ssh -p 22 ops@your-server
```

手机必须能访问该 SSH 地址。只有内网地址时，可先接通可信 VPN，不要为方便直接暴露管理服务。

安装前检查当前 DSH 包声明的 Node.js 要求，再使用兼容版本：

```bash
node --version
npm view @deepseek-ai/dsh engines
npm install -g @deepseek-ai/dsh
dsh --help
```

建议使用普通用户的 Node.js 环境安装，不默认使用 root。模型渠道和凭据也应在服务器侧配置完成。

配置好模型后，手动启动一次：

```bash
mkdir -p ~/ops-workspace
cd ~/ops-workspace
dsh web
```

根据输出确认端口及认证方式，令牌按密码保管。服务应仅监听回环地址，再经 SSH 转发访问；监听参数查看当前版本的 dsh web --help。不要直接向公网开放 DSH Web 端口。

注意：终端环境变量不会自动进入所有 SSH 非交互会话或 systemd 服务。App 托管启动时，模型凭据、Node.js 和 PATH 都要在实际启动环境中可用。不要把 Key 写进公开仓库或截图。

## 三、手机连接服务器

从 [DSH Go Releases](https://github.com/ccch1mneyyy/dsh-Go/releases) 下载匹配设备的 Android APK。选择远程主机，添加 SSH 主机，填写：

- 地址：手机实际能访问的服务器 IP 或域名。
- 端口：实际 SSH 端口，常见为 22。
- 用户：普通运维账户，例如 ops。
- 认证：当前版本支持的密码或私钥方式。
- 工作目录：服务器上的绝对路径，例如 /home/ops/ops-workspace。

工作目录不是沙箱边界，不会自动阻止工具读取账户有权访问的其他文件。

首次连接应通过可信终端或云控制台核对 SSH 主机指纹。例如，服务器使用 Ed25519 主机密钥时：

```bash
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
```

核对同种密钥类型，一致再信任。指纹意外变化时，先排查原因。

若当前版本提供实例管理选项：托管启动由 App 经 SSH 启动 DSH，适合试用；只连接则使用你已维护的服务，按界面填写端口及认证信息。长期使用更适合由服务管理器维护进程。

nvm 用户尤其要检查非交互 SSH 的 PATH。找不到 dsh 或 node 时，修正启动环境或实际程序路径，而不是反复重装 App。

## 四、第一次先做只读验证

> 请只做只读检查，不修改文件、不安装软件、不重启服务。显示主机名、当前用户、工作目录，再检查运行时间、内存及磁盘。执行前列出命令。

可检查 hostname、whoami、pwd、uptime、free -h 和 df -h。确认机器和账户正确再继续。自然语言约束不是权限隔离，仍需工具审批和操作系统权限。

## 五、实战：检查 Nginx

让 AI 先查看服务状态和最近日志，不要修改配置或重启。使用 systemd 时可检查：

```bash
systemctl status nginx --no-pager
journalctl -u nginx --no-pager -n 100
```

服务名按实际调整。需要修改时，先说明方案、备份并审查 diff，获批后检查配置，再单独确认上线。最后验证业务健康接口，失败则回滚。不要只凭 AI 的完成回复判断故障解决。

## 六、断网、排错和安全

断网不等于取消任务。重连后先核对上一次操作结果，避免重复部署。试用可用 tmux 保持终端程序；长期运行建议配置 systemd，明确账户、目录、PATH 和受限凭据。tmux 不负责开机自启，也不保证所有工具任务都能恢复。

排错顺序：网络 → SSH → DSH 服务 → 模型 → 工具权限。SSH 超时先查路由、VPN 和防火墙；服务不通查进程、地址、端口和认证；模型错误查服务器侧渠道、Key、额度及外网。后台掉线还要检查 Android 电池优化。

- 使用独立普通账户，不默认授予无限制 sudo。
- 删除、部署、重启和权限修改保留审批。
- 日志可能含业务秘密，限制读取范围，必要时先脱敏。
- 日志和网页中的指令只是待分析数据，不应改变运维目标。
- 手机启用锁屏，保护私钥和令牌，遗失后及时撤销。

## 总结

服务器安装 DSH → 配好模型 → 手机添加 SSH 主机 → 核对指纹 → 只读验证 → 按审批执行变更。手机让入口更轻，但不能让安全边界更松。
