## 这周只做一件事：不用 DSH，也试着连接模型

为什么要做这一步？如果 DSH 没回复，你需要逐渐知道问题可能在工作台，也可能在模型通道。本周用一个很短的现成程序直接访问 API，帮你区分两者。

这是 **可选付费练习**，没有预算可以先读、观察代码和做离线检查。没有真实收到回复，就不能写已经接通。这里不要求你自己从零写客户端。

## 第57天：先确认本地程序正常

在练习目录打开终端，运行 python report.py。确认仍能得到5、3、2、60。如果不会打开终端，回看第5周，别一边不确定目录，一边处理 API 问题。

用记事本打开 api_try.py，或让 DSH 只读解释：这个程序先要人同意，再问 Key，查询模型列表，然后最多发送一次短聊天请求。它不把 Key 写到文件，不自动失败重试。

## 第58天：第一次启动，但先不联网

在终端输入：

```powershell
python api_try.py
```

程序会问是否愿意继续并承担费用。**今天直接按回车，不输入 YES。**

应该显示已退出，没有调用 API。这一步是检查你会启动和取消，不需要任何 Key，不产生本程序的在线请求。

终端里的提问不是新命令：程序正在等你回答时，直接输入答案，不要在同一行再敲 python api_try.py。

## 第59天：准备安全输入

你需要第3周自己创建的 Key，以及已查看过的官方余额、价格和可用模型。Key 丢失时按平台规则处理；不要让助手找你电脑里的密钥，也不要向别人借。

getpass 可以先理解为隐藏输入：粘贴 Key 后屏幕不显示字母，通常也没有小星号，这是正常的。应在普通 PowerShell 终端运行，不在聊天框、笔记或截图里输入。

如果系统开启了剪贴板历史，密钥复制后注意按系统安全方式清理，别把含秘密的剪贴板同步到公共设备。此练习不等于企业级密钥管理。

## 第60天：愿意付费才真正执行一次

1. 再运行 python api_try.py。
2. 第一次确认时输入大写 YES，回车；随后在隐藏输入处粘贴自己的 Key，再回车。
3. 程序显示账户返回的模型列表，每个前面有数字。对照官方说明选择支持聊天补全的模型，输入对应数字。
4. 不确定就输入0取消；确定且预算允许，第二次确认再输入 YES。

**应该看到：** 一句模型实际回复，以及服务返回的用量。具体文字不同很正常。

第一处 YES 后会查询模型列表，第二处 YES 才发送聊天请求。Token 用量不是价格本身，费用要去平台核对。输出长度限制也不是账户硬预算。

## 第61天：检查结果，记最少的证据

在 learn.txt 写日期、实际模型名、成功还是失败、看到哪句无秘密的结果、是否查看账单。不写 Key，不保存整个终端截图。

如果失败，先按第3周的鉴权、余额／模型、网络三类检查。不为把任务打勾而连续运行十次；超时也不代表服务端一定没处理。

## 第62天：比较 DSH 和直接 API 调用

回答三句话：DSH 能帮我管理文件和工具；api_try.py 只做一次直接模型调用；一次 API 成功不代表 DSH 的全部能力都正常。

若直接程序成功而 DSH 失败，接着看 DSH 的提供方、模型配置和软件环境；若两边都失败，再检查账户、模型服务与网络。不要直接结论模型不聪明。

## 第63天：本周过关

能启动并取消程序；知道 Key 在哪安全输入；愿意付费时有一次真实回复；能说明 DSH 与 API 不是一个东西。未在线调用的读者写离线学习已完成、在线验证待完成。

## 今天只认识两个新词

请求：你的程序发给模型的消息。响应：服务返回的结果。以后看到 HTTP、JSON 等词，先想起这条收发过程，不必现在背完整协议。

本例程序不包含完整 Agent 循环，也不负责自动调用业务工具。面试时别把一个短请求包装成自己开发了完整 Harness。
