## 本周目标

在 DSH 工作流中加入可校验的 DeepSeek API 分类步骤，同时理解模型输出、工具调用与业务执行不是同一件事。交付 output/labels.json、分类校验测试和 docs/workflow.md。

参考分类器仅返回四类建议：access、billing、bug、other，不直接修改工单。12 条模拟输入允许发送到 API，真实业务数据必须另行授权、脱敏和合规审查。

## 先离线，再在线

```powershell
python -m unittest discover -s tests -v
python -m src.classify
```

第二条默认拒绝真实调用并返回非零，提示需要 --live，这是预期保护行为，不是程序坏了。确认第 4 周环境变量已在当前终端设置，检查模型和预算，再本人执行：

```powershell
python -m src.classify --live
$LASTEXITCODE
python -m src.evaluate
```

只有分类命令退出码为 0 且确认 output/labels.json 是本次生成，才评测。失败不会写入新结果，但旧 labels.json 仍可能存在：先看修改时间，必要时将旧文件人工归档。不要把旧成功当本轮成功。

本轮只调用一次，不自动重试。无 API 条件使用 fake transport 与现有测试，但必须标记离线模拟，不能拿它的准确率宣称真实模型效果。

## 为什么需要本地校验？

模型返回 JSON 不代表内容正确。参考实现要求顶层只有 items；每项只含 id 和 category；id 必须完整覆盖输入、不能重复或新增；category 必须在枚举内。合法 JSON 但少一条工单，仍然失败。

即便 API 支持 JSON 模式／schema 约束，仍要做本地类型、范围、业务语义与权限检查。结构正确只能排除一类错误，不能证明分类正确。

## 用 DSH 组织实际工作

```text
使用 report-check 的稳定步骤执行工单分析。
先只读调查与计划，说明哪些命令离线、哪些会调用付费 API。
统计必须由 Python 完成；模型分类只作建议。
API 步骤等待我明确批准，不读或输出任何环境变量中的凭证。
每一步检查退出码和产物；失败就停，不使用旧文件冒充新结果。
最后给出统计、分类校验状态、测试结果和需要人工审核事项。
本轮不发信、不发布、不修改业务系统。
```

你也可以由自己在独立终端执行在线步骤，再把不含秘密的产物交给 DSH 检查。这比把凭证交给 Agent 更容易划清边界。

## 面试重点：工具调用是如何发生的？

典型协议链路：应用给模型工具定义；模型返回结构化调用意图；Harness 检查工具名与参数、权限和预算；程序执行工具；把结果按协议关联回该次调用；模型继续回答或提出下一步。不能将模型返回的一段命令文本自动当 shell 执行。

本练习的 classify.py 是一次语义分类请求，不是完整 tool-calling agent loop。DSH 在外围承担执行组织；需要原生工具循环时按当前官方协议实现与测试，不能在简历上把分类器写成自研完整 Harness。

## 验收与排错

有至少四类本地校验测试；真实输出或明确的离线模拟结果；能解释模型输出与工具执行的区别；旧产物不会混入本轮证据。

若模型返回 Markdown 代码围栏而不是纯 JSON，记录为校验失败；优先改提示、使用已确认支持的结构输出能力或受限修复步骤，不用 eval，也不无限调用模型修补。
