第 12 周｜完成工程作品、面试与求职

本周目标

把十一周的练习变成可核验的工程作品，能演示、能回答追问、能解释失败，开始有针对性地投递。交付 README、作品页、5—8 分钟演示、一页简历和岗位匹配表。

先诚实区分：你使用了 DSH，不等于自研 DSH；你设计了插件契约，不等于已经实现原生插件；下载参考代码，不等于独立开发。

每日教程：第 78—84 天

天 操作 当天证据
78 清点实际功能，分成已实现、已验证、仅设计、待完成四类。确认本项目贡献与参考来源。 功能证据矩阵
79 重写 README：目标、架构、安装、命令、配置、安全、测试、评测、局限、参考。别人看它应能运行。 完整 README
80 录一段短演示：正常任务、真实工具调用、失败处理、测试和评测，不剪成虚假全成功。 演示视频或现场脚本
81 把项目写成简历条目，每个数字都有对应记录；不要写保证 100% 或完全无人值守。 一页简历
82 按下方面试题口述，不看稿；请学习助手追问，但核对其技术解释，不把它当评委权威。 不会的问题与补学计划
83 收集 10 个真实岗位，按要求与证据匹配，优先投初级 AI 应用／Agent 方向。 岗位匹配表与定制求职信
84 完成一次新目录复现和最终审查，开始小批量投递，记录反馈，规划后四周补强。 最终版本与行动计划

最终作品应具备什么？

  1. DSH + DeepSeek API 的可复现接入说明，不含 Key。
  2. 实际使用的 Skill、工作区与权限策略，并有发现／加载证据。
  3. 确定性统计工具与可校验的模型分类，清楚说明外围编排与程序边界。
  4. Git 历史、正常与异常测试，不只展示截图。
  5. 独立留出集、真实评测与失败分类，不夸大小样本结论。
  6. 一次失败恢复、交接文档与可访问静态作品页。

如果缺少真实 API 调用、Skill 加载或端到端证据，明确写未完成并补齐，不靠漂亮页面掩盖。

演示脚本：建议 5—8 分钟

第一分钟讲问题、用户、输入输出与非目标；第二分钟画 DSH—API—工具—验证的链路；接着演示一次受控任务和真实产物；再演示一次缺输入或无效响应如何失败；最后展示测试、评测、风险与下一步。

演示时使用模拟数据、已脱敏终端，不在镜头里填写 Key。现场 API 不稳定可展示预先记录的真实运行，必须明确不是实时执行；离线 fake 不能伪装成在线请求。

面试题与合格答题要点

问题 必须答到
DSH 与普通聊天工具的区别？ 工具、执行、会话、权限、反馈与验证
DSH Profile 解决什么问题？ 插件组合与配置差异，能力不只由模型决定
Skill、工具、插件分别是什么？ 工作说明、可执行能力、扩展与组合机制
工具调用如何完成？ 模型意图—参数／权限校验—执行—关联结果—继续
API 401、429、超时分别怎么查？ 鉴权、限流、网络／服务状态与安全重试
结构化输出能保证正确吗？ 只能约束部分格式，还需业务校验与人工审查
怎么处理提示注入？ 外部数据不提升指令权威，最小权限、隔离和工具校验
为什么不全用模型？ 确定性步骤用代码，语义判断才用模型
怎么证明改进有效？ 固定基线、留出集、真实运行、成本与完成率
什么时候用固定工作流而非 Agent？ 步骤稳定可确定时优先固定流程，降低成本与不确定性
如何避免无限循环？ 最大轮次、时间、预算、重复失败检测和人工接管
你具体做了什么？ 讲自己的提交、测试、设计决策和可核验证据

不必把答案背得漂亮。面试官追问一份具体日志、一段具体函数或失败案例时，你要能解释。

简历条目示例

基于 DeepSeek Harness 与 DeepSeek API 构建受控工单分析工作流，
实现确定性统计、结构化分类校验与人工审核边界；编写可复用 Skill，
建立正常／异常测试及独立留出集，记录成功率、用量和主要失败类型。
提供可复现源码、运行手册与公开静态作品页。

仅保留你真正完成的部分。数字按实际填：多少测试、多少任务、正确几条、耗时与费用。不要把教程参考实现的测试数量直接写成自己新增数量。

最终自检：是否可以投递？

给自己四项各 0—2 分：独立运行、解释核心代码、处理失败、展示真实证据。6 分以上可以尝试初级岗位，同时补弱项；这只是学习自检，不是招聘标准。

如果岗位强调平台／基础设施，下一阶段补 TypeScript／Node、服务部署、并发、持久化、鉴权、监控、容器与原生插件开发。如果偏 AI 应用，优先补真实业务建模、后端接口、评测与数据合规。

毕业标准不是读完 12 篇文章，而是能在新任务中划清边界、调用合适工具、验证结果、解释失败，并把系统交给别人继续使用。
